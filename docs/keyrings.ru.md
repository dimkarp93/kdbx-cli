# Kernel keyring

На Linux `kdbx-cli` кэширует master-пароль `.kdbx` в **kernel keyring** — подсистеме ядра, которая хранит небольшие секреты в памяти ядра. Это не демон и не файл: пароль не пишется на диск и не передаётся по D-Bus.

## Как хранится пароль

- **Где:** user keyring (`@u`). Он общий для всех процессов пользователя и живёт до перезагрузки.
- **Ключ:** тип `user`, имя `kdbx-cli:<абсолютный путь к .kdbx без симлинков>`, данные — пароль.
- **Срок жизни:** `KEYCTL_SET_TIMEOUT` = `ttl` из конфига. По истечении срока ключ удаляет ядро, а не `kdbx-cli`.
- **Права:** `3f010000` — у владельца все права, у остальных только просмотр метаданных.

В коде это `internal/keyring/kernel_linux.go`. Системные вызовы делаются через `golang.org/x/sys/unix` (`AddKey`, `KeyctlSearch`, `KeyctlBuffer`, `KeyctlInt`), без cgo.

## Утилита `keyctl`

Нужна только для ручной проверки, `kdbx-cli` без неё работает.

```sh
sudo apt install keyutils
sudo pacman -S keyutils
sudo dnf install keyutils
```

```sh
keyctl show @u
keyctl search @u user kdbx-cli:/home/me/store.kdbx
keyctl print <id>
keyctl timeout <id> 600
keyctl invalidate <id>
```

| Команда | Что делает |
|---|---|
| `keyctl show @u` | Список ключей пользователя: id, права, тип, имя |
| `keyctl search @u user <имя>` | id ключа по имени |
| `keyctl print <id>` | Данные ключа, то есть **пароль открытым текстом** |
| `keyctl timeout <id> <сек>` | Задать новый срок жизни |
| `keyctl invalidate <id>` | Удалить ключ сразу |

Удалить все ключи `kdbx-cli` проще командой `kdbx-cli forget`.

## `/proc/keys`

`keyctl` позволяет задать срок жизни ключа, но не прочитать его. Оставшееся время видно только в `/proc/keys` — виртуальном файле, который ядро формирует при каждом чтении (`proc_keys_show()` в `security/keys/proc.c`). Его читает `expiresIn`, чтобы `show` показал, сколько ещё живёт кэш.

```sh
grep kdbx-cli /proc/keys
```

```
1b2c3d4e I--Q---     1   9m 3f010000  1000  1000 user      kdbx-cli:/home/me/store.kdbx: 12
```

| Поле | Пример | Значение |
|---|---|---|
| 1 | `1b2c3d4e` | id ключа, hex, всегда 8 символов (`%08x`) |
| 2 | `I--Q---` | флаги |
| 3 | `1` | число ссылок |
| 4 | `9m` | **оставшееся время** |
| 5 | `3f010000` | права |
| 6, 7 | `1000 1000` | uid, gid |
| 8 | `user` | тип |
| 9… | `kdbx-cli:…: 12` | имя и размер данных |

Формат оставшегося времени — одно число и единица, с округлением вниз:

| Осталось | Вывод |
|---|---|
| срока нет | `perm` |
| срок истёк | `expd` |
| меньше минуты | `45s` |
| меньше часа | `9m` |
| меньше суток | `3h` |
| меньше недели | `2d` |
| больше | `5w` |

`9m` значит «от 9 до 10 минут», точнее узнать нельзя. `perm` и `expd` `kdbx-cli` считает отсутствием кэша.

## Ограничения

- Любой процесс под тем же пользователем может прочитать пароль (`keyctl print`).
- В `/proc/keys` видны только ключи, на которые у читающего есть право просмотра. Свои видны всегда.
- Без `/proc` (в некоторых контейнерах) `show` не покажет оставшееся время, но кэш работает.
- Если kernel keyring недоступен, кэш не работает и пароль спрашивается как обычно.
- `/proc/keys` — текстовый интерфейс, а не структура ABI. При любом несовпадении формата `kdbx-cli` не падает, а считает, что кэша нет.
